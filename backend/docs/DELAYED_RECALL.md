# 7일 지연 회상 평가

퀴즈 훈련 완료 후 168시간이 지난 시점부터 사진·보기 없는 자유 서술 평가를 진행합니다. 기존 퀴즈와 별도 테이블을 사용하며 성장 기록의 정답률에 포함하지 않습니다.

## 사용자 흐름

1. 새 퀴즈에서 첫 보기를 고르기 전에 ‘훈련 전에 평가 참여 등록하기’를 엽니다.
2. 사진 소유자가 확인한 사실을 한 줄에 하나씩 입력하고 확인합니다. 중복 없이 최대 30개, 각 500자입니다. 등록 뒤 수정할 수 없으며 AI 분석에서 자동 추출하지 않습니다.
3. 퀴즈 제출이 완료되면 완료 시각 + 7일이 평가 가능 시각이 됩니다. 중단된 훈련에는 아직 평가 시각이 없습니다.
4. 마이페이지 프로필 아래 평가 목록에서 직접 진입합니다. 목록에는 사진·파일명·앨범 제목을 보내거나 표시하지 않습니다.
5. 안내를 읽고 시작한 뒤 자유 서술을 작성합니다. ‘임시 저장’은 서버에 보관하며 재로그인해 이어 쓸 수 있습니다. 저장하지 않은 수정은 보존되지 않습니다.
6. 기억 없음도 제출할 수 있습니다. 최종 제출은 수정 불가이며 동일 요청 재전송은 같은 결과를 반환합니다. 여러 창의 임시 저장 충돌은 버전으로 거부합니다.
7. 담당자 채점 후 정확 회상 사실 수 / 고정된 기준 사실 수 × 100을 표시합니다. 실제 경과 시간도 표시합니다. 원래 객관식 점수와 비율을 계산하지 않습니다.

## 담당자 채점

`APP_RECALL_REVIEWER_USER_IDS=12,34`처럼 서버 환경변수로 허용된 계정 ID를 설정합니다. 기본은 비어 있으며 어느 사용자에게도 채점 권한을 주지 않습니다. 일반 사용자나 본인의 응답은 채점할 수 없습니다. 허용된 계정은 마이페이지에 채점 링크가 표시됩니다.

담당자는 제출된 답변과 기준 사실을 대조합니다. 모든 사실을 한 번씩 판정하고, 인정하는 사실은 실제 답변에 포함된 문장을 인용해야 합니다. 같은 사실 반복은 한 번만 인정하고, 동의 표현은 의미 일치 여부를 검토합니다. 애매하거나 모순된 경우 인정하지 않은 이유를 기록합니다. 최종 확정은 한 번만 가능하며 담당자 ID·시각과 사실별 판정을 저장합니다. 질문 품질에 대한 2인 평가와는 별개입니다.

## API

모든 요청은 기존 Bearer 인증을 사용하며 사용자 ID를 본문으로 받지 않습니다.

| 요청 | 용도 |
|---|---|
| GET /api/users/me/delayed-recalls | 내 평가 일정 및 점수 목록 |
| GET /api/users/me/delayed-recalls/access | 담당자 권한 여부 |
| GET /api/users/me/training-sessions/{id}/delayed-recall | 해당 훈련 예약 조회 또는 null |
| POST /api/users/me/training-sessions/{id}/delayed-recall | facts 배열과 confirmed true로 기준 고정 |
| GET /api/users/me/delayed-recalls/{id} | 본인 평가와 저장된 응답 조회 |
| POST /api/users/me/delayed-recalls/{id}/start | 서버에서 7일 경과 확인 후 시작 |
| PATCH /api/users/me/delayed-recalls/{id}/draft | version, text, cannotRecall 임시 저장 |
| POST /api/users/me/delayed-recalls/{id}/submit | 같은 형식으로 최종 제출 |
| GET /api/review/delayed-recalls | 담당자 채점 대기 목록 |
| GET /api/review/delayed-recalls/{id} | 제출 답변과 기준 사실 조회 |
| POST /api/review/delayed-recalls/{id}/grade | marks 배열로 사실별 판정 확정 |

사용자 응답 API는 채점 확정 전까지 기준 사실을 반환하지 않습니다. 채점 담당자는 제출 이후에만 볼 수 있습니다. 일찍 시작·저장·제출하는 직접 API 요청도 거부합니다. 기준이 되는 훈련 삭제·퀴즈 초기화 시 평가와 사실은 FK cascade로 함께 제거됩니다. 지연 평가는 별도의 clock 우회 설정을 제공하지 않습니다.

## 운영 범위와 한계

이 버전은 퀴즈 조건만 지원합니다. 일반 사진 열람 조건의 배정·노출 시간 기록과 비교 분석은 별도 구현이 필요하며, 퀴즈 재훈련을 일반 열람으로 표시하지 않습니다. 최초 참여 이전의 반복 노출, 대기 중 사진 재열람·재훈련은 현재 차단하거나 측정하지 않으므로 실험 운영 시 동일한 지시와 별도 기록이 필요합니다. 입력 사실의 진실성은 사진 소유자 확인에 의존합니다.

과거에 이미 완료한 훈련에는 기준 사실을 사후 등록하지 않습니다. 등록은 IN_PROGRESS 세션에만 가능하며 UI는 첫 선택 전에만 등록을 제공합니다. 현재 객관식 답안은 마지막에 일괄 저장되므로 서버는 사용자가 실제로 첫 문항을 읽기 전인지까지 증명할 수 없습니다. 엄격한 실험에서는 진행자가 사실 확인 시점을 관리해야 합니다.

중립 단서는 훈련 ID와 완료 시각으로 제한합니다. 다수 경험 중 평가 대상을 구분하기 어려운 경우 정답 사실을 드러내지 않는 동일한 안내 방식부터 연구 절차에서 합의해야 합니다. 사용자 사진과 실제 서술 응답은 저장소에 올리지 않습니다.

## 검증 명령

```powershell
cd backend
./gradlew.bat test --tests com.konkuk.memory.service.DelayedRecallIntegrationTest
cd ../frontend
npm run build
npx playwright test --config playwright.delayed.config.js
```

통합 테스트는 실제 Flyway 스키마, H2, JPA, Spring MVC와 Bearer 인증을 사용합니다. 외부 AI를 사용하지 않는 별도 테스트 컨텍스트이며 7일 경계, 기준 사실 비노출, 소유권, 초안 버전 충돌, 제출 재전송, 채점 근거와 삭제 연쇄를 확인합니다. 브라우저 테스트는 API 응답을 대체한 UI 테스트이므로 실제 배포 DB 연동 시험과 구분합니다.
